# domain/question — 문제 은행

## 책임
강의자료로 후보 문항을 만들고 **4단계 검증**을 통과한 문항만 저장·사용한다.

## 4단계
1. **생성**: Gemini가 `{문항, 정답 목록, 핵심 요소, 근거 문장}`을 만든다.
2. **코드 확인**: 근거 문장이 `material_sentence`에 실제로 있는가, 정답이 그 문장으로 성립하는가.
3. **누출 시험**: 노트가 빈 제자에게 풀게 해서 맞히면 폐기 (가르치지 않아도 풀리는 문항).
4. **외부 판정**: 문항을 만든 모델과 다른 모델이 "강의자료와 일치한다"를 판정, 일치율 기준 이상만 저장. **(Jev 보류 중)**

## 규칙
- 앞 단계에서 탈락한 문항은 다음 단계로 보내지 않는다. 단계별 결과는 `question_validation_log`에 남긴다.
- 4단계가 구현되기 전에는 1~3단계만 통과한 문항이 있다. 이 문항을 `VERIFIED`로 표시하지 말고 **외부 판정을 거치지 않았음을 상태로 구분**한다.
- 문항 상태: `VERIFIED` / `UNDER_REVIEW`(신고·이의제기) / `RETIRED`. 배틀에는 `VERIFIED`만 쓴다.
- **문항·정답·핵심 요소·개념 목록은 학생용 API 응답에 절대 포함하지 않는다.** (미리 외우거나 목록을 따라 가르치는 것을 막기 위함)
- 한 번 푼 문항은 같은 학생의 다음 배틀에서 제외한다.
- 문항 생성은 시간이 걸리므로 비동기 작업으로 돌리고, Gemini 호출 횟수를 아낀다 (단원 단위로 미리 생성).
