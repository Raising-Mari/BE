# db/migration/ — Flyway 마이그레이션

**DB 스키마를 바꾸는 유일한 방법**이다. 서버를 띄울 때 자동으로 순서대로 실행된다.

## 규칙
- 파일명: `V<번호>__<설명>.sql` (밑줄 두 개). 번호는 정수로 하나씩 올린다. 예: `V1__create_users.sql`, `V2__create_courses.sql`
- **이미 머지된 파일은 절대 수정하지 않는다.** (체크섬이 달라져 모든 팀원의 서버가 뜨지 않는다) 고칠 일이 생기면 새 번호의 파일을 추가한다.
- 번호 충돌 방지: PR을 올리기 전에 `develop`을 합쳐 최신 번호를 확인한다. 같은 번호가 있으면 내 파일 번호를 올린다.
- 문자셋은 `utf8mb4`. 모든 FK와 `ON DELETE` 정책, 조회에 쓰는 인덱스를 명시한다.
- 시각 컬럼은 `DATETIME(6)`에 UTC로 저장한다. (`created_at`, `updated_at`)
- 한 파일에는 하나의 변경 주제만 담는다. 데이터를 지우거나 컬럼을 삭제하는 변경은 PR에서 따로 강조한다.
- 롤백 스크립트는 만들지 않는다. 되돌릴 때도 새 마이그레이션을 추가한다.
- 엔티티를 고치면 같은 PR에 마이그레이션이 있어야 한다. (`ddl-auto: validate`가 서버 시작 때 확인한다)
