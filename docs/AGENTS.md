# docs/ — 팀 공유 문서

BE 레포에 두는 이유: FE·BE 팀원이 모두 보는 문서의 원본이기 때문이다.

## 현재 문서
- [erd.md](erd.md): DB 설계 (테이블·관계·JSON 구조·마이그레이션 분할)
- [api-spec.md](api-spec.md): API 목록과 핵심 로직 (**구현 전까지만 쓰는 착수용 계약서**. 구현이 시작되면 원본은 Swagger)
- [backend-plan.md](backend-plan.md): 결정 사항, 작업 순서(WP), 일정, 자르는 순서, 테스트 계획

## 규칙
- **API 명세의 원본은 Swagger(`/v3/api-docs`)다.** 같은 내용을 마크다운으로 따로 쓰지 않는다 (금방 어긋난다).
  - 예외(2026-10-31 확인): 구현 전인 지금은 `api-spec.md`가 계약서다. Swagger가 올라오면 `api-spec.md`의 엔드포인트 표와 요청·응답 예시는 지우고, 11절(핵심 로직)과 12절(오류 코드)처럼 Swagger에 담기지 않는 설계 설명만 남긴다. 이유: 이 규칙과 `api-spec.md`가 둘 다 "현재 문서"로 나열돼 어긋나 보였다.
- 여기에 두는 것: ERD, 설계 결정 기록(왜 이렇게 정했는지), 개발 계획, AI 사용·프롬프트 기록, 시험 사용 결과.
- 결정을 바꾸면 기존 문서를 지우지 말고 날짜와 바뀐 이유를 함께 적는다.
- 개인정보·API 키·실제 학생 데이터는 올리지 않는다. 시연 자료는 공개 자료만 쓴다.
- 파일명은 소문자 영문과 `-`로 쓴다. (예: `erd.md`, `decision-notes.md`)
