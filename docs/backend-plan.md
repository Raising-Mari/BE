# 백엔드 작업 계획 (착수 전)

> **상태: 설계 초안 (구현 전).** 일정은 **10/30 착수, 11/12 기능 동결**(14일)을 가정한다.
> 상세: DB는 [erd.md](erd.md), API·핵심 로직은 [api-spec.md](api-spec.md).
> 시간 추정(인일)은 AI 코딩 도구를 쓴다는 전제의 **대략치**이고, 숙련도에 따라 ±50% 흔들린다.

## 1. 결론: DB부터 시작한다

**맞다. DB 구조가 첫 작업이다.** 이유는 세 가지다.

1. 모든 API의 요청·응답과 로직이 테이블 모양을 따른다. 테이블이 흔들리면 API도 함께 흔들린다.
2. 3명이 병렬로 일하려면 **같은 테이블 정의를 공유**해야 한다. 외래키 순서 때문에 한 사람이 먼저 만들어 머지해야 한다.
3. 머지된 마이그레이션은 고칠 수 없다. 그래서 **ERD를 먼저 합의하고, V1~V8을 한 PR로 한 번에** 올린 뒤 이후 변경은 `ALTER`(V9~)로만 한다.

전체 순서는 이렇다.

```
결정 합의 → DB(V1~V8) → 공통 인프라 + AI 어댑터/텍스트 유틸 → 인증 → 과목·자료
          → 가르치기 → 문제 은행 → 배틀 → 채점 → 랭킹 → 복기 → 관리자 → 마감
```

가르치기는 **자료·문제 은행 없이도** 만들 수 있으므로 AI 어댑터(2-B)가 끝나는 대로 로직(6-A)부터 시작한다. 문제 은행과 채점이 가장 길고 위험하니 이쪽이 임계 경로(critical path)다. 위 순서도는 대략의 순서이고, 일정이 가장 빡빡해서 가르치기는 인증·과목을 기다리지 않는다. **과목·제자(WP4)를 인증(WP3)보다 먼저** 하고(시드 사용자와 dev-login으로 시험), 저장·API(6-B)만 과목·제자(WP4)를 기다린다. 두 사람이 병렬로 일하는 실제 순서는 4절이다.

DB를 확정하기 전에 아래가 정해져야 한다. 기본안으로 가도 되면 "기본안대로"라고 하면 된다.

| D-12 | 연습 배틀 | 복기 뒤 **혼자 하는 연습 배틀**(B-10)을 한다. 끝난 **`RANKED` 배틀**의 복기에서 **고른 답의 같은 문항**(틀린 답은 미리 체크, 맞힌 답도 고를 수 있음)을 **현재 노트로** 다시 풀고, Elo·전적·`user_question_history`에는 넣지 않는다. **연쇄는 안 된다**(연습 결과에서 다시 연습할 수 없다 — 사람과 한 배틀을 복기한 뒤 확인하는 과정이라서). 복기의 정답은 기본이 숨김이다. 연습의 목적이 "고친 설명으로 같은 문제를 다시 맞힐 수 있는지 확인"이라 정답을 먼저 보면 확인이 되지 않기 때문이다. **정답 보기(R-11)를 누르기 전까지는 횟수 제한 없이** 반복하며, 누르면 그 배틀의 연습은 끝난다(되돌릴 수 없음). 기록은 B-06 `mode=PRACTICE`. | 흐름도의 "연습 모드로 다시 가르치기". 랭킹 화면은 연습 배틀 기록을 보여 준다 |
| D-13 | 노트 정리 | 별도 정리 작업·알림·모순 질문은 만들지 않는다. 대신 ADD 때 **유사도 ≥0.9 자동 병합**(최신이 활성), **0.75~0.9 확인 카드**(T-05), 주차당 60개 상한(상한이어도 수정·삭제·병합은 가능). UPDATE/REMOVE는 검증을 줄인다. 상한 검사 순서는 유사도 비교 → ≥0.9 자동 병합(노트 수가 늘지 않아 검사 제외) → 나머지 `ADD`(0.75~0.9 포함)만 60개 검사·거부한다. 그래야 0.75~0.9 구간에서도 61번째 노트가 저장되지 않는다. | 흐름도의 "최신 것만 활성"·확인 카드를 가장 작은 구현으로 |
| D-14 | 배포·시연 | FE는 Vercel, 시연용 BE는 **데스크탑**. Vercel 페이지는 HTTPS라 BE도 HTTPS 주소가 있어야 하고(혼합 콘텐츠 차단), BE의 CORS에 Vercel 도메인을 허용해야 한다. DB는 MySQL 유지 (Render·Neon은 쓰지 않음) | 시연 환경이 정해져야 하고, HTTPS·CORS를 놓치면 Vercel 페이지가 BE를 호출하지 못한다 |
| D-15 | 배틀 진행 규칙 | ① 노트 스냅샷은 **각자 "준비 완료"를 누를 때** 그 사람 것만 찍고 다시 쓰지 않는다. 둘 다 준비되면 문항 선택·`RUNNING`·풀이 작업만 한다. ② 그 주차에 `ACTIVE` 노트가 **1개 이상**이어야 방 만들기·입장·준비가 된다(`BATTLE_NOTES_REQUIRED`, 연습 배틀 제외). ③ `ERROR` 배틀은 참가자 누구나 **재시도(B-09)하거나 포기(B-05, `ERROR → CANCELED`)** 한다. | 준비한 뒤 노트를 고쳐 유리해지는 구멍, 가르친 것이 없는 배틀, `ERROR`에 갇힌 방을 없앤다 |

### 각 WP의 "끝났다"는 기준

| WP | 완료 기준 |
|---|---|
| 1 | V1~V8이 빈 MySQL에서 순서대로 성공, `ddl-auto: validate` 통과, 시드 조회 가능 |
| 2-A | 토큰 없이 보호 경로 → 401, 일반 사용자가 `/api/admin` → 403, `local` 프로필에서 dev-login으로 토큰 발급(운영 프로필에는 엔드포인트가 없음) |
| 2-B | Gemini에 JSON 응답을 20회 호출해 형식 실패율 측정, 한국어 정규화·문장 분리·부정 표현·노트 유사도 단위 테스트 통과, 호출 로그 기록 |

## 5. 용량 점검과 자르는 순서 (솔직한 계산)

| 항목 | 인일 |

착수가 늦어지면 위 계산의 14일이 줄어든다. 예를 들어 11/2에 착수하면 기능 동결(11/12)까지 11일이라 2명 × 11일 = 22인일이고, P0만 약 28이므로 6인일쯤 모자란다. 착수일이 정해지면 이 표와 아래 자르는 순서를 다시 본다.

**P0만 해도 2주가 꽉 찬다.** 나의 몫이 14일을 넘고, FE의 가르치기·복기 화면까지 하면 더 초과한다. 그래서 다음을 권한다.

1. **FE 팀원이 가르치기·복기 화면까지 맡는다** (내가 BE AI 로직에 집중).
2. 지연되면 **아래 순서대로 자른다.** (위에서부터)

| 순서 | 자르는 것 | 절약 | 영향 |
